Mnemos: Sovereign memory for Hermes Agent

Your agent remembers. Only you can read it. Facts are encrypted on the machine that writes them, stored as ciphertext on Walrus, and indexed by a Sui object you own.

Get started View on GitHub

I. What it is

  1. Encrypted here

    XChaCha20-Poly1305 with keys derived from MNEMOS_SECRET by Argon2id (64 MiB, 3 passes), then HKDF-SHA256. Plaintext and the secret never leave the machine.

  2. Stored on Walrus

    Each snapshot is a ciphertext blob on Walrus testnet. The blob id is public; the bytes are unreadable without the secret.

  3. Indexed on Sui

    An owned MemoryIndex object on Sui testnet keeps blob ids, the hash-chain head, and Ed25519 signatures. It only accepts an append that links to the current head. Mnemos reads it straight from the Sui fullnode; GraphQL is only a fallback, and a stale indexer is refused rather than trusted.

  4. Restore anywhere

    Wipe a profile or switch machines. Your secret plus one object id rebuilds the local cache. Prefetch and recall stay local and never touch the network.

II. A memory you can audit

III. Quickstart

Hermes Agent 0.23.1 or newer, Python 3.11 or newer. The pure Python backend works out of the box; the Rust core is optional and opt-in.

  1. Install the plugin

    hermes plugins install https://github.com/bugnarokdev/mnemos.git \
  --ref <commit-sha> --yes-deps --enable

  2. Set your secret in $HERMES_HOME/.env

    MNEMOS_SECRET=choose-a-long-passphrase

  3. Create your MemoryIndex on Sui testnet

    cd move/MemoryIndex
sui move build --dump-bytecode-as-base64 > /tmp/mnemos-bytecode.json
hermes mnemos init --bytecode /tmp/mnemos-bytecode.json

  4. Restore on another machine

    hermes mnemos restore --object-id 0x<your-memory-index>
hermes mnemos history --verify
